# Changelog

All notable changes to Bloop are documented here. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

Entries below "## [Unreleased]" are added automatically by the recurring
autonomous dev job (branch prefix `auto/`), one line per merged PR, in the
form: `- <type>: <summary> (#<PR>)` with the originating issue noted when
applicable.

## [Unreleased]

- feat: add `Alt+Shift+ArrowDown` / `Alt+Shift+ArrowUp` to jump straight to the next/previous conversation considered unread (real server-tracked unread count OR the client-side manually-marked-unread flag from issue #86) — mirroring the Gmail/Outlook "go to next unread" convention, instead of the existing `Alt+ArrowDown`/`Up` (issue #70) stepping through every conversation one at a time regardless of read state, or having to scan the sidebar by eye for the next unread badge. Wraps around at either end; does nothing when nothing is unread. New pure `getUnreadConversationJumpDirection`/`getUnreadForDisplayConversationIds`/`getNextUnreadConversationId` helpers; listed in the keyboard shortcuts help modal. Client-side only, filtering already-loaded conversation data (issue #100)

- feat: press the Up Arrow key while the message composer is empty to jump straight into editing your own most recently sent message — matching the Discord/Slack/Twitter convention — instead of requiring a hover + click on a bubble that may have scrolled out of view. Scrolls/highlights the target message into view (reusing the existing jump-to-message behavior) and opens it in its inline edit mode automatically. Suppressed while the "@mention" autocomplete dropdown is open, since it already claims Up/Down for its own candidate navigation. New pure `findLastEditableOwnMessageId`/`shouldTriggerEditLastMessage` helpers; listed in the keyboard shortcuts help modal. Client-side only, reuses the existing `message_edit` IPC call already wired to the pencil-icon edit flow (issue #98)

- feat: add a "Mark all as read" button to the sidebar's conversation filter row — a double-check icon next to the existing "Unread only" toggle, disabled when nothing is unread, matching the Gmail/Slack convention. Clears every conversation's real server-tracked unread count via the same `message_list` + `message_mark_seen` IPC calls already used when opening a single conversation, and clears the purely client-side manually-marked-unread flag (issue #86) on every conversation that has one. New pure `getUnreadConversationIds` helper. Client-side only, no new backend surface (issue #96)

- feat: let the conversation sidebar be resized by dragging a new handle on its right edge (220px-480px, clamped), instead of it being stuck at a fixed 280px width - useful for seeing longer conversation titles/previews in full. Width persists across restarts via the same `localStorage` convention as the theme/mute/pin preferences. New pure `clampSidebarWidth`/`loadSidebarWidth`/`saveSidebarWidth` helpers. Client-side only (issue #94)

- feat: add a `Ctrl+K`/`Cmd+K` quick switcher — a centered command-palette overlay with a live-filtered text input (same title/preview substring match and pinned-first order the sidebar filter already uses), Up/Down to move the highlighted row, Enter or click to jump straight there, Escape to dismiss — matching the Slack/Linear/VS Code convention instead of switching conversations only being reachable by clicking the sidebar, focusing its filter box with `/`, or stepping one at a time with Alt+Up/Down. New pure `shouldOpenQuickSwitcher`/`buildQuickSwitcherResults` helpers and `QuickSwitcherModal` component; listed in the keyboard shortcuts help modal. Client-side only, filtering already-loaded conversation data (issue #92)

- feat: show a plain "scroll to bottom" floating button whenever the conversation timeline is scrolled away from the bottom, not just once new messages arrive — reading history with nothing new since previously left no quick way back down except manually dragging the scrollbar. Stays hidden whenever the existing "N new messages" jump-to-latest pill is already showing its own affordance, via a new pure `shouldShowScrollToBottomButton` helper. Client-side only, built on the existing scroll-position tracking used by the auto-scroll-follow behavior (issue #90)
- feat: add "@mention" autocomplete to the message composer in group conversations — typing `@` opens a live dropdown of the group's members filtered by username/display name (Arrow keys + Enter, or click, to pick one), which inserts `@username ` at the caret, matching the Slack/Discord/Telegram convention instead of mentions only being typeable blind from memory. Dismisses on Escape or an outside click, same as the existing emoji picker popover. New pure `detectMentionQuery`/`filterMentionCandidates`/`applyMentionSelection` helpers. Client-side text composition only — no new backend/IPC surface, no server-side mention parsing or notification routing (issue #88)
- feat: let a conversation be manually marked unread again — a small circle toggle next to the sidebar's existing mute/pin icons (visible on hover, shown only once a conversation has zero real unread messages) flags it with a dot badge, Gmail/Outlook "mark as unread" style, until it's opened again (which clears the flag the same way actually reading it would). Counts toward the existing "Unread only" filter (issue #76) and its badge count. New pure `toggleManuallyUnreadConversationId`/`loadManuallyUnreadConversationIds`/`saveManuallyUnreadConversationIds`/`isConversationUnreadForDisplay` helpers, persisted per-user via the same `localStorage` convention as the existing muted/pinned conversation sets. Client-side only (issue #86)
- feat: show an unsent draft as the sidebar conversation preview ("Draft: ...", amber text) instead of the stale latest-message preview, Telegram/WhatsApp-style, so a conversation left mid-compose is easy to spot again instead of looking unchanged. A live typing indicator still takes priority over the draft line. New pure `buildConversationPreviewLabel` helper, reusing the existing per-conversation `drafts` state already used to restore composer text. Client-side only (issue #84)
- feat: show a dismissible in-app toast (sender, short preview, resolved conversation title) when a message arrives in a conversation other than the one currently open — click it to jump straight there, or let it auto-dismiss after 6s. Respects the existing muted-conversations preference and the message's fail-closed verification status (never previews a removed/unverified message), and renders inside the app's existing focus-loss privacy-blur container so nothing leaks while the window is unfocused. New pure `shouldShowMessageNotificationToast`/`buildMessageNotificationPreview`/`appendMessageToast`/`dismissMessageToast` helpers; new `MessageToastStack` component. Client-side only, driven by the already-arriving realtime message upsert event — no new backend/IPC surface (issue #82)
- feat: add a show/hide toggle (eye icon) to the auth screen's password field — click to reveal the typed characters as plain text, or mask them again, matching the Chrome/1Password convention instead of the field only ever rendering as bullets. New pure `resolvePasswordInputType`/`getPasswordVisibilityToggleLabel` helpers. Client-side UI state only — doesn't touch the split-credential auth derivation, so the server still never sees the raw password either way (issue #80)
- feat: focus the sidebar's "Filter conversations..." box with a bare `/` keypress, matching the Slack/Linear/GitHub "jump to search" convention instead of it only being reachable by clicking in. Suppressed the same way the existing `?` shortcuts-help shortcut is while typing in an editable field, via a new pure `shouldFocusConversationFilter` helper; listed in the keyboard shortcuts help modal. Client-side only (issue #78)

- feat: add an "Unread only" toggle to the sidebar's conversation filter row — a pill button (mail icon, badge shows the total unread-conversation count) that, when active, hides every conversation with zero unread messages, mirroring the Gmail/Slack "unreads only" convention. Combines with the existing text filter and pinned-sort order rather than replacing them, via a new pure `filterUnreadOnlyConversations` helper. Client-side only, filtering already-loaded conversation data (issue #76)

- feat: add a password strength meter to the registration form's password field — a 4-segment bar (red/amber/indigo/green) plus a Weak/Fair/Good/Strong label, shown only in "Create Account" mode once something is typed, via a new pure `assessPasswordStrength` helper scoring length milestones and character-class variety. Purely client-side guidance; doesn't relax the existing 8-char minimum validation or touch the split-credential auth derivation — the server still never receives the raw password either way (issue #74)
- feat: add a search/filter box above the group drawer's contact lists (the "New Group Chat" picker's "Select Contacts" list, and "Group Settings" > "Add Contacts") once there are more than 5 contacts to scan — case-insensitive substring match against display name or `@username` via a new pure `filterContacts` helper, same filter convention as the sidebar's existing conversation filter and the Pinned-messages subtab filter, so a large contact list no longer has to be scrolled by eye to find one person. Client-side only, filtering already-loaded contact data (issue #72)
- feat: switch between conversations in the sidebar with `Alt + ArrowDown` / `Alt + ArrowUp` — steps to the next/previous conversation in the sidebar's current (pinned-first) order, wrapping around at either end, matching the Slack/Discord channel-switch convention instead of the list only being reachable by clicking. New pure `getAdjacentConversationId`/`getConversationSwitchDirection` helpers; documented in the keyboard shortcuts help modal. Client-side only (issue #70)
- feat: add a filter/search box to the Pinned subtab, shown once a conversation has more than one pinned message — case-insensitive substring match against the pinned message's text and sender display name via a new pure `filterPinnedMessages` helper, mirroring the sidebar's existing conversation filter convention. Client-side only, filtering already-loaded pinned-message data (issue #68)
- feat: highlight the matched substring inline (via `<mark>`) wherever an active in-conversation search query occurs in message text, in addition to the existing jump-to + ring-highlight on the active match's bubble — matching the Chrome/Firefox/Slack in-page-find convention, so a match inside a long message is easy to spot instead of only the whole bubble being called out. New pure `splitTextForSearchHighlight` helper; combined with the existing URL auto-link splitting so highlighting and clickable links coexist. Client-side only, against already-decrypted/already-loaded message text (issue #65)
- feat: mute a conversation to stop it inflating the global unread badge/title — a new bell icon next to the sidebar's existing pin icon toggles a per-user, locally persisted muted set via new pure `toggleMutedConversationId`/`sumUnreadExcludingMuted` helpers (same `localStorage` convention as pinned conversations). A muted chat keeps its own unread count once opened, but that count no longer feeds the nav-rail total or the window/document title's `(N) Bloop` prefix (issue #42); its sidebar badge renders gray instead of accent-colored, with a bell-off icon next to the title so it stays discoverable. Client-side only — desktop OS notification suppression is a separate, Rust-owned concern and out of scope (issue #63)
- feat: open the in-conversation message search bar with `Ctrl+F` (`Cmd+F` on macOS) — a new pure `shouldOpenConversationSearch` helper, matching the browser/Slack/Discord "find" convention instead of the search bar only being reachable via the chat header's small search icon. Active regardless of focus (no suppression while typing, since the modifier means the browser wouldn't type an "f" into the field anyway), and only fires while a conversation is selected. Client-side only (issue #61)
- feat: float recently-used emoji to the front of the composer's quick emoji picker — tracking usage via new pure `recordRecentEmoji`/`buildEmojiPickerOrder` helpers and persisting the list via `localStorage` (same global convention as the dark/light theme preference), so the emoji someone actually reaches for are one glance away instead of scattered through the fixed 16-emoji grid. Client-side only (issue #58)
- fix: persist the dark/light theme preference across app restarts — toggling the Sun/Moon button in the nav rail previously reset to dark every time the app reopened (hardcoded `useState(true)`); now saved via new pure `loadThemePreference`/`saveThemePreference` helpers (same `localStorage` convention as pinned conversations), falling back to the OS `prefers-color-scheme` on first-ever launch instead of always defaulting to dark. Stored globally rather than per-user since the theme also applies to the unauthenticated login screen. Client-side only (issue #56)
- feat: pin a conversation to the top of the sidebar — a pin icon on hover (filled and always visible once pinned) toggles a per-user, locally persisted pinned set via new pure `togglePinnedConversationId`/`sortConversationsForSidebar` helpers; pinned conversations float to the top while the relative order of everyone else is preserved. Client-side only, distinct from the existing per-message pin feature (issue #53)
- docs: finish Private Talk to Bloop rename across the remaining plain-text/metadata mentions — governance docs (`.specify/memory/constitution.md`), feature specs (`specs/001..004`), bug reports (`.specify/bugs/*`), `Cargo.toml` description/authors, the capabilities description, a Rust panic message string, and a SQL schema comment. Internal Rust/Tauri identifiers (crate name, bundle identifier, DPAPI session folder, custom media protocol scheme, `PRIVATE_TALK_*` env vars) and `.github/workflows/release.yml` intentionally left unchanged — no local cargo/rustc to compile-verify Rust changes, and no `workflow` OAuth scope to modify the release workflow (#52)
- feat: add a quick emoji picker to the message composer — a new emoji button opens a popover with a curated set of common reaction emoji; clicking one inserts it at the current caret position (via a new pure `insertTextAtCursor` helper, not just appended to the end), and Escape closes the popover ahead of the existing cancel-reply/clear-attachment Escape behavior. Client-side only (issue #50)
- feat: add a keyboard shortcuts help modal — opened via a new NavRail button or the conventional `?` key (suppressed while typing in an input/textarea/select or contenteditable field, via a new pure `shouldOpenShortcutsHelp` helper), listing the composer/timeline/search shortcuts (Enter to send/save, Shift+Enter for a newline, Escape to cancel, Up/Down/Enter to step search matches) that were previously only discoverable by accident, matching the Slack/Discord/Linear convention. Client-side only (issue #48)
- feat: show a network connectivity banner — a persistent "You're offline" warning while `navigator.onLine` is false (sends/realtime silently stop working otherwise with no explanation), and a brief auto-dismissing "Back online — you were offline for \<duration\>" confirmation on reconnect, via a new pure `formatOfflineDuration` helper. Client-side only (issue #46)
- feat: show the full weekday/date/time (e.g. `Thursday, November 20, 2025 at 2:32:45 PM`) as a native hover tooltip on message bubble timestamps — including the verification-failed and removed-message timestamp lines — so the exact second and full date are available on demand without adding always-visible chrome to the compact `HH:MM`/"Yesterday" label. Client-side only, pure `formatFullMessageTimestamp` helper (issue #44)
- feat: reflect the total unread message count in the window/document title (e.g. `(3) Bloop`, reverting to plain `Bloop` once everything is read) via a new pure `computeDocumentTitle` helper, so there's a way to tell at a glance whether anything new has arrived while the app is minimized, behind other windows, or just unfocused — matching the Slack/Discord/Gmail tab-title convention. Client-side only (issue #42)

- feat: auto-link `http(s)://` URLs inside message text as real, clickable anchors (underlined, opens in a new tab, `rel="noopener noreferrer"`) instead of rendering them as inert plain text — trailing sentence punctuation and wrapping parens are kept out of the link. Client-side only, pure-function text segmentation (`splitMessageTextIntoLinkSegments`), no `dangerouslySetInnerHTML` (issue #39)
- feat: show an inline "New messages" divider in the timeline, anchored above the first message that was unread when the conversation was opened (Slack/Discord-style), so the viewer knows exactly where to start reading instead of only seeing a sidebar unread badge. Client-side only, snapshotting `unread_count` before it's reset by marking messages seen (issue #37)
- fix: message editing now uses an auto-growing textarea (Shift+Enter for a newline, Enter to save) instead of a single-line text input, so multi-line messages can actually be edited without losing their line breaks (issue #35)
- feat: add in-conversation message search — a search icon in the chat header opens an inline bar that filters the currently-loaded message history by text, shows an `N of M` match counter, and steps through matches with the up/down buttons or Enter/Shift+Enter/Arrow keys, jumping to and highlighting each one the same way "jump to pinned message" already does. Client-side only, matching against already-loaded messages — no new backend search endpoint (issue #33)
- feat: the composer is now a drag-and-drop target for attachments — dragging a file from the OS file explorer over it shows a dashed-border highlight, and dropping it stages the file exactly like the paperclip picker (same MIME/size validation, now shared via a new `validateAttachmentFile` helper instead of being duplicated) (issue #31)
- feat: the staged attachment chip in the composer now shows a real thumbnail for images (generated client-side, never touching Tauri IPC) and a generic file/video icon badge otherwise, instead of just a bare filename — makes it easier to confirm the right file is about to be sent before it's encrypted (issue #29)
- feat: clicking an image attachment now opens a full-screen lightbox (Escape, close button, or backdrop click to dismiss) so the full, uncropped image can be viewed instead of the cropped `max-h-72` inline thumbnail; videos are unchanged since `<video controls>` already has native fullscreen (issue #27)
- feat: pressing Escape now also cancels an in-progress message edit, or dismisses a pending "Confirm remove" prompt, without needing the mouse — same convention as the composer's reply/attachment Escape handling (issue #25)
- feat: pressing Escape in the composer now cancels an active reply (or clears a staged attachment if no reply is active) without needing the mouse, matching Slack/Discord/Telegram conventions (issue #22)
- chore: add a dev-only Playwright screenshot harness (`harness.html`, `scripts/harness-main.tsx`, `scripts/screenshot-component.mjs` — `npm run screenshot`) for capturing before/after PNGs of a single component in isolation, to attach visual diffs to PRs. Not part of the shipped app build.
- fix: stop composer draft text from leaking between conversations when switching without sending; unsent drafts are now kept per-conversation and restored on return
- feat: show date context ("Yesterday", "Nov 18", or "Nov 18, 2025") ahead of the time on message bubbles once a message wasn't sent earlier today, so scrolling into older history no longer shows a bare, date-less `HH:MM` (issue #18)
- feat: show a soft character counter under the composer once a draft gets long (amber past 80% of a 4,000-char guidance limit, red past it), purely informational — sending is never blocked since no server-side text length cap is enforced (issue #20)
